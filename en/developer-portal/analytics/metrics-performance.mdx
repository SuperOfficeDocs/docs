## At a glance

The **API Performance tab** shows API-level application performance for one specific application.

<GoToAppPage />

2. Select **API metrics**, then select **API Performance** tab.

3. Select a time range interval (minutes, hours, or days).

4. Click through the environment specific buttons.

### Columns

| Type of usage | Description |
|---|---|
| Operation Name | The API endpoint. |
| Count | The number of API invocations to the endpoint. |
| Record Count | The number of database records selected by the API invocation. |
| Duration (AVG) | The average number number of milliseconds elapsed for each of all API invocations. |
| Customer | The customer context identifier that invoked the API. |

<Tip>
Click on a row to observe the samples (individual invocations) related to the endpoint.
</Tip>

When there are many rows, you can filter the list by typing in the search box. The list will update as you type.

## Log all API calls (turn off sampling)

To keep telemetry manageable, SuperOffice samples the API calls your application makes. When there is a lot of traffic, only some calls are stored in full, and each stored call stands in for several similar ones. The totals on **API Performance** and [Failures][2] still show the real numbers, but a particular call may not show up in **Samples** or in the end-to-end transaction view.

When you're troubleshooting, you can turn sampling off for a limited time so that every API call your application makes is logged.

### When to use it

* A customer reports a failing or slow request and you need to find that exact call.
* You are checking a fix and want to see every call, not a sample.
* You need exact numbers (call counts, durations, records returned) for a short period.

### How to turn it on

<GoToAppPage />

2. Select **API metrics**.

3. Click the **Settings** (cogwheel) button.

4. For each environment (SOD, Stage, Production), choose the date and time when full logging should stop. Leave the field empty to keep normal sampling.

    ![Turn off adaptive sampling of API calls -screenshot][img4]

5. Click **Apply**.

### Good to know

* Full logging stops by itself at the time you chose, and normal sampling starts again. You can also stop it early by clearing the date.
* You can turn it off for at most 2 weeks ahead.
* It is set per environment and covers all tenants using your application in that environment.
* It can take a few minutes after saving before full logging starts.
* It does not change the [API Usage][1] numbers or anything you're billed for. Those are never sampled.
* You need **Write** access to application usage to change it. Users with read access can only view the dates.

<Tip>
Turn it on just before you reproduce the problem, and only for as long as you need. Pick the environment you are testing in. Usually that's SOD or Stage, not Production.
</Tip>
