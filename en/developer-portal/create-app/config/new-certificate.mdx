The certificates in your application configuration are **RSA encryption keys**. You need the private key to [sign system user tokens][2] in server-to-server applications and database mirroring.

The Developer Portal stores your public key. However, you must store the private key.

<NoteClearToReplace />

## Add a new certificate

Use this when the environment doesn't have a certificate yet.

<GoToAppPage />
2. Select **Configuration** > **Authentication**.

    ![Secrets and Certificates -screenshot][img1]

3. Click **New Certificate**.

    ![New Certificate dialog -screenshot][img2]

4. Enter a description and expiration, and then click **Add**.

    ![Certificate card -screenshot][img3]

    <NoteExpiration />

5. Store the **private key** somewhere safe! You can't look it up in the Developer Portal later.

6. In the **You have unsaved changes** bar in the lower-right corner, click **Save Settings**.

    * If the new certificate is for **SOD only:** No further action is needed.
    * If the certificate is for **stage, production, or all environments:** You must request publishing.

## Renew a certificate

Use this to replace an existing certificate, for example before it expires or if the private key is compromised. You no longer need to delete the old certificate first.

<GoToAppPage />
2. Select **Configuration** > **Authentication**.

3. On the card of the certificate you want to replace, click the renew icon (<i class="ph ph-arrow-clockwise" aria-label="Renew"></i>), next to the trashcan.

    ![Certificate card with renew and delete icons -screenshot][img3]

4. A renew popup opens with the old description filled in. Update the description and expiration if needed, then click **Renew**.

    <Warning>
    The current certificate stops working when the new version of the configuration is published.
    </Warning>

5. A message at the top of the page confirms that a new certificate was generated and that the old one stops working after Publish.

6. Store the new **private key** somewhere safe! You can't look it up in the Developer Portal later.

7. In the **You have unsaved changes** bar in the lower-right corner, click **Save Settings**.

8. Update your application with the new private key before the new version is published, so that it keeps working when the old certificate stops working.

Renewing works the same way in SOD, Stage, and Production.
