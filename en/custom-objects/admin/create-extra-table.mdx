<Note>
Extra tables require the CRM Suite **Growth** plan or higher, or a user-plan based license with [Development Tools][8].

With a user-plan based license, extra tables are available in SuperOffice Service, and in SuperOffice CRM through [web panels](#web-panel). To use them as custom objects in SuperOffice CRM, join the [custom objects pilot program][9].
</Note>

You store your own types of data in extra tables. You create the table in **Tables** and [add fields][1] to it.

In the CRM Suite, an extra table becomes a [custom object][3], like companies and sales. Users can open it from <i class="ph ph-list" aria-label="Main menu"></i> > **Custom objects** and from the Navigator, create records from **New**, search for them in **Find**, select them in relation fields, and see related records on section tabs. The steps to create the table are the same regardless of license. Table properties and role permissions decide how users view and work with it.

## Naming conventions

<Warning>
Choose database table names carefully. You **cannot change** them later.
</Warning>

Use logical names, so it is easy to see what the database contains. The **y_** prefix prevents conflicts with future SuperOffice table names. It does not prevent conflicts between extra tables from different third parties.

* Must start with **y_**
* May contain only underscores, the letters a to z, and numbers

## Steps

1. <GotoTables />

1. Click **New table**.

    ![Tables screen with the New table button -screenshot][img1]

1. In the **Table properties** screen, configure the new table.

    * Enter a *name* to be used as the label.
    * Enter a *description* that explains what the table is for, so other administrators understand it.
    * Enter a *database table* beginning with **y_** to identify it in the schema.
    * To let users find the custom object, [choose an icon](#icon) and [opt to show the table in the Navigator and Find](#navigator).
    * Optionally set [other properties](#properties).

    <Note>
    Some table properties cannot be set until you have added fields.
    </Note>

1. Click **OK** to save the new table (runs `create table y_mynewtable ...`).

1. [Add fields to your new table][1].

1. Select the table name in the list to reopen the **Table properties** screen. Now that the table has fields, you can use them instead of the ID:

    * In **Sort order**, choose the field to sort the records on.
    * In **Display field**, choose the field that identifies a record when the table is shown in another table.

    ![Display field list with the fields of the table -screenshot][img4]

1. Click **Restart NetServer**. If Travel is activated, you will also see a message that a new Travel database must be generated.

1. If the table is a custom object, [give roles access](#access-rights) to it.

The table is ready to use. In the CRM Suite, optionally customize the layout of the custom object in the [Screen Designer][5].

## Table properties {#properties}

| Property | Description |
|---|---|
| Folder | To place the table in an existing folder, select a folder from the list. |
| Name | The UI label of the table. |
| Description | What the table is for. Fill it in so other administrators understand it. |
| Database table | The name of the table in the database. It can only be set during creation and **cannot be changed**. |
| Search header | The header used in the search screen for this table. |
| Header for viewing entry | The header used when you display an entry in this table. |
| Header for new entry | The header used when you create a new entry in this table. |
| Header for editing entry | The header used when you edit an entry in this table. |
| Sort order | The column the table is sorted on. If you check **Descending**, the values are sorted in descending order. For numerical values, this means the highest value will appear at the top of the table. The table must contain fields before you can select anything here. |
| Display field | When data from this table is shown in another (related) table, you need to choose the field to display in that table. The table must contain fields before you can select anything here. |
| Parent field | Used in connection with hierarchical tables. |
| Full name |  If this is a hierarchical table, this field can specify a field that is automatically updated with the entry's full name based on the name field for this entry, and all parent entries. |
| Hide ID field | If selected, the ID field will not be shown when listing entries in the table. |
| Hide the table | If selected, the table will not be visible from **System design** > **Tables**. |
| Show table in Find | If selected, users can search for records in this table in **Find**. |
| [Show in navigator](#navigator) | If selected, the table is listed in the Navigator and under **New**. |
| [Icon](#icon) | The icon shown for the table in the Navigator and other places. |
| Enable batch webhook in Service | If selected, batch updates on this table will trigger [webhooks][2]. |

## Choose an icon {#icon}

The icon is shown in the Navigator, the custom objects list, context menus, the webhook event list, and the Screen Designer.

1. Open the table properties and select **Icon**.

1. In the **Select icon** dialog, choose an icon:

    * **Default icons:** a selection of common icons.
    * **Full icon library:** search the full library, or browse by category.
    * **Custom icons:** upload your own SVG file, up to 50 KB.

1. Click **Apply icon**.

To go back to the default icon, click **Remove icon**.

![Select icon dialog with the Default icons, Full icon library, and Custom icons tabs -screenshot][img2]

## Show the table in the Navigator and Find {#navigator}

The table can be listed in the Navigator and under **New** in the top bar, and its records are added to history and favorites like other records. To enable this, select **Show in navigator** in the table properties.

To let users search for its records in **Find**, also select **Show table in Find**.

![Show table in Find, Show in navigator, and an icon selected in the table properties -screenshot][img3]

## Give roles access {#access-rights}

Users can see and work with a custom object only if their role gives them access. After you create the table and add its fields, set the permission for each role that should use it.

1. <OpenRoles />

1. Select a role from the list.

1. Go to the **Custom objects rights** tab.

1. In the **Permission** list next to the custom object, choose what users with this role can do: **Read**, **Create**, **Update**, or **Delete**.

See [data rights for custom objects][4] for what each permission allows.

## Show table in a web panel {#web-panel}

With a user-plan based license, you show extra tables in SuperOffice CRM through web panels. To set the relevant access rights, the user must belong to a role that has the functional rights **List tables** and **Edit tables**.
