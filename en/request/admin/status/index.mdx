All requests that are registered in SuperOffice have a status, such as **Open**, **Closed** or **Postponed**. Select **Request** in the navigator and in the **Request status** tab, you can see the request statuses already defined in the system, and create additional request statuses. A request status must be linked to one of the system's internal statuses, such as **Open** or **Closed**. Each internal status must be linked to at least one request status.

For example, you can create a new status called "Waiting for reply" as a more detailed variant of either **Closed** or **Open**, depending on how you want the system to process and report this status internally. You can also link custom logic to such statuses to streamline your business processes.

## Settings

| Setting | Description |
|---|---|
| Name | The name of the request status. By default each internal status has a request status with the same name. |
| Internal status | The system's internal statuses. Each internal status must be linked to at least one request status. The system statuses **Merged** and **Deleted** are only used for merged requests and deleted requests respectively, and are not visible to the users. |
| Default | Indicates if this is a default status for the internal status. |
| Queue status | Indicates if requests with this status should be placed in the queue. Relevant if you use the **Get next request in queue** function. |
| Track time as | Used to report time usage in various phases of request management. The system calculates time used both in relation to defined "opening hours" and the whole 24-hour period. Choose from: in queue and awaiting processing; at internal decision stage; at external decision stage |

## Default status for new requests and replies {#default-status}

When you create a request, its status is set in this order:

1. The category's **Default status for new request**, if the request type allows that status.
1. The request type's **Default status**.
1. Your preference **Default status in new request**, if the request type allows that status.
1. If none of these apply, the request is saved as **Open**.

The status is set when the **New request** screen opens. Changing the category or request type afterward does not change it.

When you reply to a request, the status is set in this order:

1. The category's **Default status for new message**, if the request type allows that status.
1. Your preference **Default status for new message**, if the request type allows that status.
1. If neither applies, the status is unchanged.

A request type's **Available statuses** limit the defaults. A category or preference default that is not in the list is skipped.

A default status can be a postponed status with a postpone option, such as **1 week**. The option comes from the same setting as the status, and the **New request** screen shows it before you save.

<Note>
Split requests and split messages keep the status and postpone date of the original request. Requests created from incoming email are set to **Open**. If an [email filter][4] has **Close request** checked, they are set to **Closed** instead. Default statuses are not used in these cases.
</Note>
