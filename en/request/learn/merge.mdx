You can merge two or more requests. For example, if multiple contacts in the same company have reported the same technical issue (via phone, web forms and email), you can merge these requests into one request to process. Contacts and messages from all merged requests will be kept.

<Note>
You can also search for and select requests to merge from the search results screen or lists. Then click the **Task** button in the lower left corner and select **Merge requests**.
</Note>

## Steps

1. [Open one of the requests][1] you want to merge.

1. Click <i class="ph ph-dots-three-circle-vertical" aria-label="Task menu"></i> and select **Merge**. A screen opens, showing the fields that must be merged. Now you need to find the request to merge with this one.

1. In the search field, start typing a request name or enter a request ID. Enter **%** to display all requests.

1. Select a request from the list of search results.

1. To add more requests, repeat the previous steps.

1. Click **Merge**. The requests are merged.

The request IDs that were overwritten will no longer be available in favorites and history lists and regular search. If you enter an overwritten request ID in the search field, you are redirected to the merged request.

## Tabs after a merge {#tabs}

On the Request screen, the tabs of the requests that were merged into another request close, also when they are pinned. You are not asked to confirm. If you were viewing a request that was merged away, the request it was merged into opens in its place.

## Primary request {#primary-request}

The request with the earliest registered date is automatically the primary request, and the other requests are merged into it. Customers and colleagues refer to the original request number, so this keeps the request number they know.

![Merge requests dialog where the oldest request is selected as the primary request -screenshot][img1]

When you merge exactly two requests, you can click the arrow icon <i class="ph ph-arrows-down-up" aria-label="Reverse direction"></i> in the **Merge requests** dialog to reverse the direction, so the newest request becomes the primary request.

The behavior is controlled by the preference **Use the oldest request as the main request when merging**, which is enabled by default. To change it:

1. Go to <i class="ph ph-user-circle" aria-hidden="true"></i> **Personal settings** > **Preferences**.

1. Select **Request**, and set **Use the oldest request as the main request when merging** to **Yes** or **No**.

1. Click **Save** to apply your changes.

![Request preferences with the option to use the oldest request as the main request when merging -screenshot][img2]
