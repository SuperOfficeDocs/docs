Our ticketing system allows you to efficiently handle incoming requests and helps you offer outstanding customer service every day. This selection of how-to guides contains guidelines to help you keep track of, answer and analyze all incoming questions and inquiries using SuperOffice Service. No matter whether they come in by phone, email, chat, web form, or other channels.

**Requests** is one of the main features of SuperOffice. Here you manage requests and enquiries that are in the system. You can also create internal and external requests, respond to incoming enquiries and obtain an overview of the statuses of all requests in the system.

Each question and query can be defined as a request. These questions range from support issues, questions about the product and services, or questions about invoices. Whenever a request comes in, you want to handle them as quickly and efficiently as possible and professional customer service. Previewing a request from a list also lets you send a [quick reply][28] without leaving it, so you can keep moving through a busy queue.

![The Request screen with the Unassigned requests list and a preview of the selected request -screenshot][img1]

<Note>

The Request screen is being introduced gradually. If you do not see it yet, you work with several requests in horizontal tabs. The left panel, the **Overview** tab, and Mentions are not available.

</Note>

## Where can I access requests? {#open}

* Section tabs in the Company, Contact, Sale, and Project screens.
* [Standard lists][35], such as **Own open requests**
* [Search][12]
* [Favorites][18]
* [Flagged messages][5]

A request you open from any of these opens in a tab on the Request screen. For all the ways to look up requests, see [Find a request][47].

### Contacts {#customers}

Requests can be linked to [contacts][14], who in turn can belong to a [company][13]. This means that requests cannot be linked directly to companies (only indirectly via contacts). When new emails are imported and saved as requests, the request is automatically linked to the correct contact via the email address. When you view a request, it is easy to see who the contact is, and if you click the contact's name, you can see which other requests are registered for this person. This provides you with a rapid overview of previous communication with this same contact.

## The Request screen {#request-screen}

The Request screen is where you work with your requests. It has three areas:

* **Left panel:** Vertical tabs for the requests and selections you work with, and a search field for finding others. It also has the entries **Overview**, **Find request**, and [Mentions][36]. See [Work with overview pages][30] for how tabs, pinning, and search work.

* **Main area:** Shows the **Overview** tab, a selection or list of requests in board view or list view, or one request as a Request card.

* **Side panel:** The [side panel][31] on the right shows the company and contact of the request you are working on. It closes while the **Overview** tab is shown, and opens again when you leave the **Overview** tab if it was open before.

### What you see the first time {#first-time}

The first time you open the Request screen, the horizontal tabs you had open are copied to the left panel. Pinned tabs stay pinned. The **Overview** tab opens if you have no open tabs. Your old tabs are not changed.

To get an overview of your requests and work with them in tabs, see [Work with requests][42].

## The Request card {#request-card}

The Request card shows one request at a time, as a tab on the Request screen. It has the following sections:

* [Request header](#header): the title, contact, and company, with buttons to favorite, pin, reload, and edit the request, and the **Task** menu.
* [Request properties](#properties): the fields that route and prioritize the request, such as Status, Owner, and Category.
* [Messages](#messages) tab: the messages on the request, with buttons to reply, forward, and add comments.
* [Details](#details) tab: all fields registered for the request.
* [Change log](#log) tab: everything that has happened to the request since it was registered.
* **Related requests** tab: [linked requests][21] (parent, child, or related).

### Request header {#header}

The header of the request shows the title, the contact, and the company defined when the [request was created][4]. It also has these buttons:

* <i class="ph ph-star" aria-label="Star icon"></i>: Sets the request as a favorite. The request is then accessible via **My favorites** on **Requests** in the Navigator, and in the **My favorites** tile on a [dashboard][17].
* <i class="ph ph-push-pin" aria-label="Pin icon"></i>: Pins the request in the left panel.
* <i class="ph ph-arrow-clockwise" aria-label="Refresh icon"></i>: Reloads the request.
* <i class="ph ph-pencil-simple" aria-label="Pencil icon"></i>: Edits the request.
* <i class="ph ph-dots-three-circle-vertical" aria-label="Task button"></i>: Opens the **Task** button menu. See [Task options](#task-options).

### Messages tab {#messages}

The **Messages** tab shows the messages on the request. At the top of the tab, you can [reply][46], forward, and add comments as internal messages.

You can change how many messages are expanded. See [Personalize request handling][41].

#### Message types

There are three types of messages:

* **Enquiries** from contacts or other external parties
* **Replies** to these enquiries, possibly asking for more details
* Internal comments about the request, such as questions to a colleague

<Tip>
Internal messages are marked with <i class="ph ph-dots-three" aria-label="Three dots"></i>.
</Tip>

#### Message tasks

Click <i class="ph ph-dots-three-vertical" aria-label="More options"></i> (More options) on a message to access additional options for the message:

* **Change**: Click here to [edit][9] or delete the message.
* **Reply**: Click here to reply the contact in the To field.
* **Reply all**: Click here to replay all contacts in the To, Cc and Bcc fields.
* **Forward**: Click here to [forward the message][8].
* **Email header**: Click here to view the email header.
* **Show**: Click here to view the message in a new window/tab.
* **Split message**: Click here to [split the message][19] and create a new request. Useful if a message contains two issues that should be handled by different departments, for instance a technical question and an invoice question.
* **Print message**: Click here to print the message.

#### Request Insight {#sentiment}

Request Insight analyzes the sentiment of incoming email requests, so you can prioritize the customer who needs you first. An emoticon in the message header shows the detected sentiment:

* Negative <i class="ph ph-smiley-sad" aria-hidden="true"></i>
* Neutral <i class="ph ph-smiley-meh" aria-hidden="true"></i>
* Positive <i class="ph ph-smiley" aria-hidden="true"></i>

<Note>
Request Insight requires a Text Services license, or CRM Suite Core. If you do not see the emoticon, ask your administrator to [enable text analysis][43].
</Note>

#### Translation Assist {#translate}

Translation Assist detects the language of an incoming request and shows it below the message. If the message is in a language you cannot read, select **Translate from** ***language*** below the message. The subject and body are translated and added below the original message.

<Note>
Translation Assist requires a Text Services license, or CRM Suite Core. If you do not see the detected language, ask your administrator to [enable text analysis][43].
</Note>

### Details tab {#details}

The **Details** tab contains an overview of all the fields for the request.

### Change log {#log}

<Note>

The Change log requires a **Service Premium** license or the **Growth** plan.

</Note>

This screen shows the log for this request. All events are recorded, including when they occurred, what happened and who was responsible.

![The change log on a requests shows all the different changes done on the request -screenshot][img2]

### Request properties {#properties}

The **Request properties** panel has the following fields:

* **Request type:** The [type][40] of the request. You can change the request type here.

* **Status:** Shows the status of the request. You can change the status here.
  * **Open:** The request is in progress.
  * **Closed:** The request was fully answered.
  * **Postponed:** Action on the request was [postponed][38] to a future date, when it is set back to **Open**.

* **Owner:** The name of the request handler who is responsible for the request is given here. You [can change the owner][7] here.

* **Category:** The [category][25] that the request belongs to appears here. You can change the category here.

* **Priority:** Choose between **Low**, **Medium**, and **High**, or you can make the system assign the priority automatically. This can be done, for example, on the basis of [escalation levels][24] set for different contacts and companies.

* **Access level:** Select one of the following options:
  * **External:** Select this option if the contact is to have access to the request via the SuperOffice Customer Centre.
  * **Internal:** Select this option if the contact is not to have access to the request. The request will be listed in SuperOffice Customer Centre, but the contact cannot view the request details or messages.

* **Tags:** In the **Tags** list box, [select relevant tags][22] for this request.

#### Category Insight {#categorization}

Category Insight analyzes incoming email requests and suggests a category based on their content. It does not apply the category automatically.

<Note>
Category Insight requires the SuperOffice AI Platform and a Categorization license, or CRM Suite Growth. If you do not see suggestions, ask your administrator to [train the model and enable suggestions][44].
</Note>

1. Open an incoming email request and look for a suggested category in the request footer.
1. Review the suggestion. If it fits the request, select the category link to apply it.
1. Check the category on the request. The suggestion disappears after you apply it.

![Suggested category in a request footer -screenshot][img3]

If no category matches, no suggestion appears. You can still choose a category yourself.

#### Summary Assist {#summary}

Summary Assist summarizes the messages in a request, so you can act on it without reading the full thread.

<Note>
Summary Assist requires a Text Services license, or CRM Suite Core. If you do not see it, ask your administrator to [enable text analysis][43].
</Note>

With CRM Suite, you find Summary Assist in the **Reply Assist** panel:

1. In the **Request properties** panel, click <i class="ph ph-sparkle" aria-label="Reply Assist"></i> in the icon bar on the right to switch to **Reply Assist**.
1. Click **Summarise**.
1. Review the summary of the request's messages.

To draft a reply from the same panel, see [Reply Assist][45].

### Task options {#task-options}

Click the **Task** button (<i class="ph ph-dots-three-circle-vertical" aria-label="Task button"></i>) in the header of the request to access the following options:

* **Edit**: Click here to edit the properties for this request. For example, you can assign the request to another request handler if you need to [ask a colleague for advice][7].
* **Accept**: Click here to [take over the request][1]. You will then be the request's new owner.
* **Relate**: Click here to [link the request][21] to another request.
* **Split**: If a single request contains several questions, for example, if the customer first asks a technical question and then uses the opportunity to raise an invoicing query, you can [split the request][11] into two using this button.
* **Merge**: Click here to merge this request with one or more other requests. For example, if multiple contacts in the same company report the same technical issue (via phone, web forms and email), you can [merge these requests][16] into one request that will be processed. The oldest request becomes the primary request by default.
* **Print**: Click here to print the request.
* **Delete**: Click here to delete the request.
* **Mark as Spam**: Click here to [mark the request as spam][27].
