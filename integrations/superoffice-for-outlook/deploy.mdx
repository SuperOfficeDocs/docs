You can perform centralized deployment through the Microsoft 365 Admin Center.

<Tip>
Install for a single user instead? [Go to the user guide][5].
</Tip>

## Choose how to install {#install-options}

You can add SuperOffice for Outlook for your organization in two ways:

| Install method | How updates reach your users |
| --- | --- |
| From Microsoft AppSource (recommended) | New features and fixes reach your users automatically. When an update needs new permissions, Microsoft notifies you in the Microsoft 365 admin center, and you approve it. |
| Custom install (you upload the manifest file or add it from a URL) | New features and fixes reach your users automatically. Manifest updates aren't guaranteed to reach them. Apply each new manifest yourself. |

The manifest is the file that tells Outlook what the add-in can do and which permissions it needs. SuperOffice updates it only occasionally, when a new feature needs it. Until your organization applies the update, that feature doesn't appear for your users, even though the version number in SuperOffice for Outlook shows the latest release. For example, [shared mailbox support][21] and the [archive reminder][14] both needed a manifest update.

## Approve manifest updates {#approve-updates}

When a manifest update needs new permissions, a Microsoft 365 administrator must approve it before it reaches your users.

1. Sign in to the Microsoft 365 admin center.
1. Go to **Settings** > **Integrated apps**.
1. Select **SuperOffice for Outlook** and accept the update.

After you accept the update, it can take up to 72 hours to reach all users. Some users get it before others. This is expected.

## Switch from a custom install to AppSource {#switch-to-appsource}

If your organization uploaded the manifest itself, switch to the AppSource install so manifest updates reach you automatically.

1. Note which users and groups have access to the add-in.
1. In the Microsoft 365 admin center, remove the custom-installed SuperOffice for Outlook add-in.
1. Deploy SuperOffice for Outlook from AppSource to the same users and groups. See [Microsoft's documentation][3].
1. Allow up to 72 hours for the add-in to reach all users.

<Tip>
Make the switch outside working hours, for example before a weekend, so users aren't left without the add-in during the workday.
</Tip>

## Deploy via Microsoft 365 admin center

To deploy SuperOffice for Outlook using the Microsoft 365 admin center, see [Microsoft's documentation][3].

## Approve shared mailbox permissions for users

Shared mailbox support requires additional Microsoft 365 permissions. A Microsoft 365 Global Administrator must grant consent for the add-in before users can access shared mailbox features.

Consent can be granted in three ways:

* Using a generic authorization URL (recommended - can be done before users encounter any prompts)
* Using a URL that a user copies from the permission dialog they encounter
* Directly from the add-in in Outlook, using a Global Administrator account

If a user does not have admin rights, they can select **Return to the application without granting consent** in the dialog, then copy a link to share with their Microsoft 365 Global Administrator.

For full step-by-step instructions, see [SuperOffice for Outlook: Authorization guide][6].
