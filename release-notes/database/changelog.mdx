### SuperOffice

**Step 160**

Remove VisibleFor rows whose record no longer exists, and keep only the newest VisibleFor row for records that have more than one

A record has exactly one VisibleFor row; several rows per record have never been supported. Rows left behind by
deleted records break that as soon as the id is reused: appointment, sale and selection queries join VisibleFor,
so the extra row duplicates the record and can hand out the stale row's visibility. Saving and deleting those
records keeps the rule; this removes the rows already in the database, for every table VisibleFor points at.

**Step 161**

Increase length of login.ns_secret from 2000 to 4000 characters, to fit bearer-token secrets

A bs1: bearer-token secret is the token plus a third for base64, so 2000 leaves too little headroom for access tokens.

* Modify table login
ns\_secret

**Step 162**

No longer used; appointment.ticket_id is added by step 163

**Step 163**

Add appointment.ticket_id, linking an appointment to a request (one request, many appointments); nullable like sale_id and project_id. Drops the NOT NULL version from step 162 first, if present

* Modify table appointment
ticket\_id, ticket\_id

**Step 164**

Add functional right 'Can override approval text in forms'

Adds the 'forms-override-approval-text' functional right with its name and tooltip; the role admin only lists
rights that have both. It is deliberately not linked to any role, not even admin-all: it must be granted
explicitly per role in the role admin.

**Step 165**

Replace the freetextindex (table_id, record_id) index with one that also covers ownerrecord_id, contact_id and freetextindex_id. Deferred: applied right after a legacy freetext wipe, or at the start of a full merge on a nearly empty index; otherwise pending until a later plain AddIndex/DeleteIndex step

The freetext merge and incremental indexing read index entries by (table_id, record_id); the new index covers every field they
read, so those reads need no key lookups. Building it on a large freetextindex would hold up an upgrade, so both changes are
deferred: applied right after a legacy freetext wipe, or at the start of a full merge on a nearly empty index. Otherwise they stay
pending until a later plain AddIndex/DeleteIndex step.

* Modify table freetextindex

**Step 156**

Repair person.activeInterests and contact.activeInterests where the denormalized counter disagrees with the number of interest link rows whose list item is not deleted, which is what draws the interest indicator in lists. Corrects the descriptions of those fields, which claimed the counter equals the raw number of link rows

Bug 118450 (merging moved the interest link rows at row level without recounting) and Bug 21531 (deleting an
interest list item left the counters of everyone linked to it untouched) are fixed in code; this repairs the
rows that have already drifted.

* Modify table person
activeInterests
* Modify table contact
activeInterests
* Modify table personinterest

**Step 158**

Prime LocaleText resourceIds 26/28/29 (PushNotificationTextResources.TicketRequestIdentity/TicketTakenOverTitle/TicketTakenOverTitleGeneric) for the TicketCustomMessage/TicketTakenOver mobile push notifications added in PR 48936. English (1033) only - resourceId is not scoped per typeid in this table, so a full re-sync of every existing typeid=41 row (not just an incremental Truncate_field on the new resourceIds) is required to avoid deleting unrelated rows that reuse the same resourceId under a different typeid (e.g. 26/28 already exist under typeid 7/11/12). The other 15 languages need translation before the next full re-sync of this typeid.

roles get it by assignment in the role admin.
