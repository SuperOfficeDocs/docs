## Summary of highlights

**SuperOffice 12** - a new main version of SuperOffice CRM where we focus on AI to become part of how you work every day.

From this version, all feature updates are available to SuperOffice Online customers only. Onsite installations will receive security updates only.

## Feature updates

### Reply to requests directly from the preview - Service

Working through a request queue just got faster. You can reply to a request straight from the preview panel - no need to open the full request and lose your place in the list.

* A Quick reply button is available when you preview a request from a request list or in split view.
* Clicking it opens a compact reply editor right in the preview, so you can write and send your answer while staying in the list.
* Replies sent this way are registered on the request exactly like a reply from the full request view — including status updates, and the list refreshes automatically.
* If you cancel or move to another request with unsent text, you'll be asked before anything is discarded.
* Quick reply is not shown on requests that are marked as spam, deleted or merged, so you're never offered an action that doesn't apply.

**Why it matters**
Agents handling high volumes of requests can triage, read and respond from one place, cutting down on clicks and context switching. This brings back a much-requested capability from the previous Service client.

### Forms - Conditional fields in Forms - Marketing

Part of the broader Forms improvement initiative to cater to more professional marketing needs. Long forms with fields that don't apply to every visitor feel overwhelming and hurt completion. Conditional fields let a form only show a question when an earlier answer makes it relevant, so each visitor sees just what matters to them while the form still captures the detail needed from everyone else.
Where to find it: Marketing → Forms → form builder. On any eligible field's option/value, choose Add related field.

**How to use it:**

*	Works on dropdowns (including standard fields), radio buttons, checkboxes, rating fields (stars/smileys/dice/thumbs), extra fields (dropdown or Boolean type), and Interests fields.
*	Eligible field types are shown with a badge when adding a new element, so users don't have to add a field first to find out.
*	A related field appears indented below its parent, with a plain-language condition banner (e.g. "This field shows when 11–50 employees is selected"). Multiple trigger values join with "or"; rating fields use a range instead of a single value.
*	Fields can be chained several levels deep (question → follow-up → deeper follow-up), though each related field is controlled by exactly one condition on one field.
*	For the visitor: hidden by default, appears instantly on the triggering answer, and disappears and clears if the answer changes. A hidden field is never required, even if marked mandatory, and hidden answers aren't included in the submission.

### Forms - AI styling of Forms - Marketing

AI styling of forms shipped as a beta in 11.13 — a user gives a website URL and the AI suggests colors, borders, and rounded corners to match it. For 12.4 it's graduating out of beta: the results are more consistent and polished than in the original beta, and the panel is now clearer about what's AI-generated and what applying it will do, so users can trust the suggestion and know what they're getting before they commit to it.

Where to find it: Marketing → Forms → edit a form → Style tab → Custom styling section.

**How to use it:**

*	Enter a website URL and select Generate CSS.
*	The AI analyzes the site and proposes CSS; preview before applying.
*	Select Apply now to override the form's default styling with the result. It only changes colors, borders, and rounded corners. Other styling needs to be changed in the basic styling section, or added as additional CSS properties (font, layout such as width/height, etc.).
*	The panel now states plainly that this overrides the form's default styling, and carries an AI-attribution badge so it's clear the suggestion came from AI analysis of the given site rather than a manual choice.

### Flows - expanded trigger conditions for custom fields - Marketing

Broadening what you can build flow logic on. Extra fields of the dropdown type can now be used as a trigger condition on a Form submission, so you can filter or branch a flow based on the answer given.

**Where to find it:** Flows → a trigger based on a Form submission → trigger condition on a dropdown-type extra field.

**How to use it:** Select a dropdown-type extra field as a condition on a Form-submission trigger; its list values now populate so you can filter or branch on the answer given.

### Multiple DKIM for Mailgun <Badge icon="gear" color="orange">Settings and maintenance</Badge>

Send outgoing mail in Service and Marketing **from several domains** - such as separate brands or country-specific addresses - with each domain signed by its own DKIM key, instead of sharing one key across your SuperOffice environment.

Without multiple DKIM, all outgoing mail is signed with a single domain's DKIM key, even when it is sent from a different brand or country-specific address. This **weakens DKIM and DMARC verification** for any domain other than the one the key belongs to, which can affect deliverability.

To set this up, **request a DKIM setup** for each sending domain using the [Order DKIM key form][9], listing the domains involved - for example brand1.com, brand2.com, and brand3.no. **SuperOffice Operations** will create the domains in Mailgun, generate a DKIM key for each one, and send you the DNS records to add. Your DNS administrator adds these records following the [DKIM][10] and [SPF][11] setup guides. Once SuperOffice Operations **confirms the records are valid**, the domain is ready to use.

<Note>
Remember to add the different domains in **Settings and maintenance** > **Lists** > **Mailing domains**, and add your different mailboxes in **Settings and maintenance** > **Requests** > **E-mail**.
</Note>

![Settings and maintenance for multiple domains is set up in Requests > Email and Lists > Mailing domains -screenshot][img11]

Learn more about [multiple DKIM records][12].

</Update>

### Dashboard - Measure sale cycles {#12.2-core-1} <Badge icon="user" color="blue">Sales</Badge>

Understanding how long deals take to close helps you spot what's working and where deals stall. The **Sale cycle** field shows the number of days from when a sale is created until it's set to **Sold** or **Lost** - the count appears once the sale reaches one of these statuses, rather than running while it's still open. For open sales, use the **Days in stage** field instead.

Without this, tracking cycle length across reps, teams, and segments means piecing information together by hand. The **Sale cycle** field puts this on the dashboard, so the pattern is visible at a glance rather than something you have to dig for.

You'll find it in the **Dashboard** module, as a filter in **Find**, and as a column in archives.

Two ready-made tile templates in the **Library** make it easy to get started:

* My average sale cycle per sale type this and previous year
* My group's average sale cycle per sale type this and previous year

For example, a sales manager could add the group tile to compare how cycle length trends across teams and use that to sharpen forecasting.

![Dashboard with My average and my groups sale cycle -screenshot][img1]

![Dashboard tile edit for sale cycle -screenshot][img2]

#### Find - Sale cycle as criteria and column

The **Sale cycle** criteria and column let you see how long a sale has been open. Because the field shows a number of days, you can search between, above, or below any figure you choose.

Adding **Sale cycle** as a column in your sale selections gives you a quick view of how long each sale has been in progress, right alongside the rest of your results.

![Use Sale cycle as criteria to set up sale selections -screenshot][img3]

<Note>
The **Sale cycle** shows 0 days until the sale is set to **Sold** or **Lost**. For **open** sales, use the **Days in stage** field instead.
</Note>

### Email and Document - Download the email or document file {#12.2-core-2} <Badge icon="user" color="blue">Core CRM</Badge>

Sometimes you need a copy of an email or document outside SuperOffice - to forward it another way, archive it locally, or open it in a different tool. You can now **download** the email or document file from any archive where you see it, and from the document dialog.

Downloading an email lets you open the stored message in your local email client. As **Outlook Mail Link (OML)** is phased out, this gives you a straightforward way to keep working with emails in your local Outlook installation.

In any archive that shows documents and emails, the context menu includes a **Download** option. Multi-select isn't supported.

An email in the **Inbox** also has the **Download** option in the **Task** menu.

### Mailing - View numbers with two decimal in Summary <Badge icon="bullseye" color="purple">Marketing</Badge>

A mailing's **Open rate** and **Click-through rate** are shown to two decimal places, giving an exact read on how recipients responded rather than a rounded approximation.

Rounding these rates to the nearest whole percentage can hide real differences in performance, especially for smaller mailings where each recipient shifts the percentage by several points. Showing the full two decimal places removes that ambiguity, so the number on screen matches the actual count of opens and clicks.

Find these figures on the **Summary** tab of a mailing, under **Marketing** > **Mailings**.

Both rates are calculated as a percentage of the number of recipients the mailing was sent to. For a mailing sent to seven recipients, five opens is shown as an **Open rate** of 71.43%, and two clicks is shown as a **Click-through rate** of 28.57%.

![Mailing summary showing Open rate and Click-through rate to two decimal places -screenshot][img12]

Learn more about [mailing reports][13].

<Tip>
You can also set up the **Dashboard tiles** (Mailing - Average xx tiles) with decimal to get more accurate numbers.
</Tip>

### System design - Webhooks management panel {#12.1-admin-1} <Badge icon="gear" color="orange">Settings and maintenance</Badge>

The **Webhooks** panel gives administrators a visual way to manage, monitor, and recover webhooks without writing code or using the API.

Go to **Settings and maintenance** > **System design** > **Webhooks** to see all configured webhooks in a sortable, filterable overview. Each row shows the webhook name, health status, target, subscribed events, last delivery time, last event, and consecutive errors for the last 24 hours.

![Settings - Webhooks panel overview -screenshot][img8]

Health status is color-coded: green for healthy, amber for active with failures, grey for manually stopped, and red for automatically deactivated.

To **create and edit webhooks** you get a guided form. Select the events to subscribe to by entity type, set the destination as an external HTTPS URL or a CRMScript, and test the connection inline before saving. A primary error notification email address is required - the form cannot be submitted without one. Additional CRM users (in your company) and external email addresses can be added as recipients, and you can choose whether to be notified by email, in-app, or both.

The **context menu** gives you options to edit, copy, toggle the active/stopped state, restart, or delete a webhook. Copying a webhook creates a duplicate with a "(copy)" suffix in stopped state.

![Settings - Webhook details and settings -screenshot][img9]

<Note>
After 9 consecutive delivery failures, the system automatically deactivates the webhook. A red banner on the webhook shows the failure count and last error in plain language. Use the **Restart** button to re-enable it.
</Note>

When a webhook is automatically deactivated, all users configured to receive notifications for that webhook get an in-app banner notification with a direct link to the delivery log for that webhook.

The **Events** tab shows the full delivery history - timestamp, status, attempt count, and error code. Failed events can be retried individually. The list can be exported to CSV.

Read more about [managing webhooks][7].

</Update>

### Spam classification on requests {#12.0-service-1} <Badge icon="ticket" color="green">Service</Badge>

The **Mark as Spam** action lets users classify fraudulent or unwanted requests. Spam requests are excluded from all views, searches, reports, and selections.

You'll see **Mark as Spam** in the context menu for requests in your lists, in the **Task** menu on one request, and in the Task menu on request selections.

Once you select **Mark as Spam**, a confirmation dialog (Yes/No) appears to confirm that you want to set the request(s) as spam.

![Request list showing the Mark as spam context menu -screenshot][img10]

* Only users with the **Can mark requests as SPAM** functional right can classify requests. The right is configured by an administrator per [role][8] in Settings and maintenance.

* Requests marked as spam move to the **Recycle bin**, where you can **restore** them if needed. Find the **Recycle bin** in your **Personal settings** menu.

* The spam requests are **permanently deleted** from the Recycle bin after a configurable period. The default is 14 days.

</Update>
